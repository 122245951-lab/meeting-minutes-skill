## 定位
Word 制式纪要是「一键四件套」之外的**可选第五件**，面向需要归档、打印、走审批流或对外发送的正式场景。

- 与**正式纪要**的区别：正式纪要追求完整可存档（详细版可达数千字，含来源标注、执行提示、推断声明）；Word 版追求**两页 A4 内读完**，是精简投影，去掉一切过程与佐证。
- 与**一页速览卡**的区别：速览卡是纯文本要点，Word 版是可归档的制式表格文档，有表头、有签批栏、可直接打印。
- **不默认输出**：必须先询问用户，用户明确需要才生成。

## 触发与询问
- **时机**：一键四件套交付完成后发起，与「是否将模板保存为个人预设」合并为**一次询问**，不额外增加打扰轮次。
- **话术**：

```
另外，是否需要输出一份 Word 版制式会议纪要（表格型，控制在 2 页 A4 内，内容精简）？
需要的话我直接生成 .docx 交付；不需要请回复"不用"。
```

- 用户答「需要 / 要 / 生成」→ 按本规范生成。
- 用户答「不需要 / 不用 / 不用了」→ **不生成**，直接结束，不再追问。
- 用户未回答该问题 → 视为不需要，不阻塞主流程。

## 硬性约束（两页 A4）

### 页面与排版
| 项 | 规范 |
| --- | --- |
| 纸张 | A4 纵向 |
| 页边距 | 上下 2.0 cm，左右 2.2 cm |
| 标题 | 宋体/黑体加粗 16 pt，居中，段后 6 pt |
| 一级板块名 | 加粗 12 pt，段前 8 pt 段后 4 pt |
| 表头 | 加粗 10.5 pt，浅灰底纹 `D9D9D9`，居中 |
| 正文 | 10.5 pt（中文宋体，西文 Times New Roman） |
| 表格行距 | 固定值 16 pt；单元格垂直居中，左右内边距 0.08 cm |
| 表格样式 | `Table Grid`，全框线，表头行重复（跨页时自动带表头） |
| 签批栏 | 最后一张表，无框线或浅框，留出手写/签名空间 |

### 内容配额上限
超出配额即压缩，**不得因内容过多溢出到第三页**：

| 板块 | 配额上限 |
| --- | --- |
| 会议基本信息表 | ≤ 8 行 |
| 一、议题与结论表 | 每议题 1 行，≤ 6 行 |
| 二、关键决议表 | ≤ 10 行 |
| 三、行动项表 | ≤ 14 行 |
| 四、遗留问题表 | ≤ 5 行 |
| 正文叙述段落 | ≤ 3 段，每段 ≤ 2 行 |

### 生成工具
统一使用 **python-docx** 生成 `.docx`（`Document()` → `add_heading` / `add_table` / `table.style = 'Table Grid'` / 单元格底纹走 `w:shd` XML）。不依赖 Word COM、不依赖 pandoc。

### 生成后校验
生成完毕必须回读校验，不做"生成完就交付"：
1. 用 python-docx 重新打开，统计表格数、总行数、段落数。
2. 按下述粗估规则判断是否超页：
   - A4 纵向高 29.7 cm，上下页边距各 2.0 cm → **可用正文高度 25.7 cm**。
   - 单行高度：固定行距 16 pt（16 pt ≈ 0.565 cm）+ 表格框线约 0.015 cm ≈ **0.58 cm/行**。
   - **单页容量 ≈ 25.7 ÷ 0.58 ≈ 44 行；两页容量 ≈ 88 行。**
   - 统计「所有表格行数（含表头）+ 段落行数 + 标题与板块名折算行」，再按**长单元格折行**经验系数 **×1.25** 折算。
   - **折算后 ≤ 80 行**视为可安全落在 2 页内；> 80 行即需压缩。
3. 估算超 2 页 → 按「压缩优先级」裁剪后重新生成，**不交付超页版本**。
4. 有条件时用 LibreOffice / Word 转 PDF 实测页数复核；无转换条件时以上述估算为准，并在交付回复中说明「页数为估算值」。

## 内容结构（固定六段）

```
【会议纪要】{会议主题}（{日期}）          ← 标题，居中
┌──────────┬────────────────────────┐
│ 会议名称 │ ……                     │   ← 会议基本信息表（2 列）
│ 会议时间 │ ……                     │      行：名称/日期/时间/地点/主持人/
│ 会议地点 │ ……                     │      记录人/参会人/评审范围
│ 主持人   │ ……                     │
│ 记录人   │ ……                     │
│ 参会人员 │ ……                     │
└──────────┴────────────────────────┘

一、议题与结论                            ← 每个议题一行
┌────────┬────────────┬──────────────┐
│ 议题   │ 核心讨论   │ 评审结论     │
├────────┼────────────┼──────────────┤
│ ……     │ ……         │ 通过 / 调整后通过 │
└────────┴────────────┴──────────────┘

二、关键决议                              ← 决议三件套在 Word 版保留「事项 + 决策人」
┌────┬──────────────────┬────────┐
│ #  │ 决议事项         │ 决策人 │
└────┴──────────────────┴────────┘

三、行动项
┌────┬──────────┬────────┬──────────┬────────┐
│ #  │ 事项     │ 负责人 │ 完成时限 │ 状态   │
└────┴──────────┴────────┴──────────┴────────┘

四、遗留问题
┌────┬──────────┬────────┬────────────┐
│ #  │ 问题     │ 责任人 │ 处理建议   │
└────┴──────────┴────────┴────────────┘

┌──────────────┬──────────┬──────────┐
│ 主持人签字   │ 记录人   │ 日期     │   ← 签批栏
└──────────────┴──────────┴──────────┘
```

### 各段填写规则
- **会议基本信息表**：沿用 Step 3 提取的五要素；素材未提供的写「待补充」，不编造。参会人一行内全列，不折行罗列。
- **一、议题与结论**：一行一议题。「核心讨论」只写该议题暴露出的**最关键 1 个问题**（一句话，≤ 30 字），不写讨论过程；「评审结论」写「通过 / 调整后通过 / 待补充规则后通过」等状态短语。
- **二、关键决议**：决议数 ≤ 10 时全列；超过 10 条按模块归并（同模块多条合并为一条，措辞压成一句）。每条决议压到一行、≤ 40 字。决策依据**不在 Word 版出现**。
- **三、行动项**：事项描述压到 ≤ 25 字。完成时限沿用推算日期时，在日期后加「（推算）」。状态列填「未开始」（Word 版不填临近/逾期，避免打印后失效）。
- **四、遗留问题**：只保留中高严重度；处理建议一句话，≤ 25 字。
- **签批栏**：固定三列，留空待签署。

## 精简原则
1. **去过程**：Word 版只呈现"议题 → 结论 → 行动"的结果链，讨论过程、争议、澄清问答全部省略。
2. **去佐证**：来源标注（转录第 N 段）、决策依据、执行提示、推断声明全部省略，版面优先。
3. **去修饰**：不用 emoji、不用高亮块、不用彩色字体；仅表头浅灰底纹。
4. **保留标记**：推算类日期、待补充字段必须保留原标记，避免读者误认为是会议原始承诺。
5. **数字与人名优先**：精简时优先保留负责人、日期、金额、倍数等硬信息，压缩的是描述性文字。

## 压缩优先级（超页时按序执行）
按 1 → 5 顺序裁剪，每执行一步重新估算行数，达标即停：

1. **决议归并**：同模块多条决议合并为一条，措辞压成一句（16 条 → 5–8 条）。
2. **议题表瘦身**：删掉「核心讨论」整列，只留「议题 / 评审结论」两列。
3. **行动项描述压缩**：事项描述从 ≤ 25 字压到 ≤ 15 字，只留动作 + 对象。
4. **遗留问题裁剪**：只留高严重度（≤ 3 条），处理建议压到 ≤ 15 字。
5. **行动项摘取**：按推算截止日期升序排序，只保留最近的 10 条，并在表下加注「本表列出最近 10 项，完整 14 项见飞书纪要」。

## 与一键四件套的关系
- Word 版是同一份提取结果的**精简投影**：不新增事实、不新增推断、不新增素材未提及的因果。
- 决议三件套在 Word 版中只保留「事项 + 决策人」，**依据列省略**（依据留存于正式纪要）。
- 来源标注在 Word 版中**全部省略**，保持版面整洁。
- 推算类日期、待补充字段的标记**必须保留**，与正式纪要口径一致。
- Word 版生成后，飞书文档的「一键四件套」内容不变，不回写、不覆盖。

## 文件命名与交付
- 命名：`【会议纪要】{主题}-{日期}.docx`，例：`【会议纪要】会员体系2.0版本PRD评审会-2026-09-03.docx`
- 生成后用 `present_files` 交付，并在回复中说明：总行数、估算页数、是否触发了压缩及压缩了哪一项。
- 用户后续要求修改 Word 版时，重新生成整个文件，不做局部 patch。
