## 定位与目标
可视化卡片是一键四件套的第四件，定位为**「一页看懂会议全貌」的静态 HTML 卡片**。
- 与速览卡的区别：速览卡是纯文本要点列表，可视化卡片用图形、色块、进度条、分布图表等视觉元素呈现，信息密度更高、更直观。
- 与正式纪要的区别：正式纪要追求完整可存档，可视化卡片追求"一眼抓住重点"，不展开细节。
- 目标受众：所有参会人及未参会但需要快速了解会议结果的人。

## 卡片结构
卡片自上而下分为以下模块（带 ※ 的为条件输出，素材无对应内容时不显示）：

```
┌─────────────────────────────────────────────┐
│  ① 顶部信息栏（标题/日期/类型/行业/参会人数） │
├─────────────────────────────────────────────┤
│  ② 核心结论区（1-3 条，大字突出）            │
├──────────────┬──────────────────────────────┤
│  ③ 决议概览  │  ④ 待办状态分布（进度环/条形） │
│  （列表+决策人）│                            │
├──────────────┴──────────────────────────────┤
│  ⑤ 风险与待确认 ※（标签+严重度色标）         │
├─────────────────────────────────────────────┤
│  ⑥ 发言人角色分布 ※（有说话人标签时显示）    │
├─────────────────────────────────────────────┤
│  ⑦ 底部行动提示（最近截止的待办/待确认）     │
└─────────────────────────────────────────────┘
```

## 各模块规范

### ① 顶部信息栏
- **会议标题**：`【会议纪要】{主题}`，字号最大，加粗。
- **元信息行**：日期 · 会议类型 · 行业风格 · 参会人数 · 主持人（如有）。
- **视觉**：浅色背景条，左侧可加会议类型图标（用 emoji 或纯文字标签）。
- **多语言**：双语时标题双语并列，元信息用主语言。

### ② 核心结论区
- 提取会议最核心的 1-3 条结论（从决议结论中筛选最重要的）。
- 每条结论一行，前面加彩色圆点或编号，字号大于正文。
- 不超过 3 条；超过 3 条时只放最重要的，其余归入决议概览。
- 结论必须是素材中明确达成的，不编造。

### ③ 决议概览
- 列出本次会议的全部决议（决议三件套：事项/决策人/依据）。
- 每条决议用卡片或列表项呈现：事项加粗，决策人用标签，依据用小字灰色。
- 决议数量多时折叠为"共 N 项决议，点击展开"（静态卡片中则全部列出，控制字号）。
- 无决议时显示"本次会议未形成明确决议"。

### ④ 待办状态分布
- 统计待办事项的状态分布：已过期 / 临近（7天内）/ 未到期。
- 用横向堆叠条形图或环形图呈现比例，旁边标注各状态数量。
- 同时显示待办总数和已明确负责人的比例。
- 无待办时显示"本次会议无待办事项"。
- 颜色规范：已过期=红色（#EA6668），临近=橙色（#FAAD14），未到期=绿色（#52C41A）。

### ⑤ 风险与待确认 ※
- **风险**：素材中提到的风险与遗留问题，每条用标签呈现，按严重度（高/中/低）加色标。
- **待确认事项**：每条含事项内容+跟踪人+预期解决时间，预期时间临近的加红色标记。
- 风险和待确认分两列或上下排列。
- 素材中无风险和待确认时，本模块不显示。

### ⑥ 发言人角色分布 ※
- 仅在转录含说话人标签且已完成角色识别时显示。
- 呈现各角色的人数分布和发言占比（用横向条形或饼图）。
- 角色：主持人 / 决策人 / 执行人 / 记录人 / 旁听。
- 标注关键角色姓名（如"决策人：张三"），不列出所有发言人。
- 无说话人标签时本模块不显示。

### ⑦ 底部行动提示
- 列出最近 1-3 个即将到期的待办或待确认事项（按截止时间排序）。
- 格式：`📅 {日期} · {事项} · {负责人}`。
- 已过期的置顶并标红。
- 无待办/待确认时显示"暂无即将到期的行动项"。

## 设计原则
- **一页原则**：所有内容在一屏内呈现（桌面端约 700-900px 高），不滚动或仅轻微滚动。
- **色彩克制**：主色不超过 2 个（一个主题色 + 状态色），状态色仅用于待办状态和风险严重度。
- **信息层级**：标题 > 核心结论 > 决议/待办 > 风险/角色 > 底部提示，通过字号和粗细区分。
- **数据准确**：所有数字（待办数、决议数、参会人数、比例）必须来自提取结果，不编造。
- **条件渲染**：素材没有的内容不显示对应模块，不留空白占位。
- **静态优先**：不依赖 JavaScript 交互，纯 HTML+CSS 即可完整呈现；可选加极轻量的 hover 效果。

## 多语言适配
- 输出语言为英文时，所有标签和标题用英文（Decisions / Action Items / Risks / Pending / Attendees）。
- 中英双语时，核心模块标题双语并列，内容用主语言，关键术语保留原文。
- 数字和日期格式跟随输出语言（中文用"2026年9月2日"，英文用"Sep 2, 2026"）。

## 条件输出模块汇总

| 模块 | 显示条件 | 不显示时的处理 |
| --- | --- | --- |
| ⑤ 风险与待确认 | 素材含风险或待确认事项 | 整个模块隐藏 |
| ⑥ 发言人角色分布 | 转录含说话人标签且角色识别完成 | 整个模块隐藏 |
| 决议概览中的决策依据 | 素材中有依据 | 显示"依据：待补充" |
| 待办状态分布 | 有待办事项 | 显示"本次会议无待办事项" |

## HTML 实现约束
- 使用独立 HTML 文件，内联 CSS，不依赖外部库（纯 HTML+CSS 实现图表）。
- 最外层 `<html style="margin:0;padding:0;">` + 透明 div，与可视化 skill 规范一致。
- 宽度自适应（`width:100%`），最小宽度 320px，最大宽度 800px 居中。
- 高度由内容自然撑开，不写死高度。
- 字体使用系统字体栈：`'PingFang SC','Segoe UI',Arial,sans-serif`。
- 用 CSS 渐变、flexbox、border-radius 实现卡片视觉，不用图片。
- 图表用纯 CSS 实现（堆叠条用 div 宽度比例，环形图用 conic-gradient）。
- 文件命名：`meeting-visual-card-{主题缩写}-{日期}.html`。
