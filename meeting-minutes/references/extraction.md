## 清洗规则
对原始素材（转录全文 / 杂乱笔记）先做清洗，再做提取：
- **去口头语**：去掉"嗯、啊、那个、就是说、然后然后"等填充词，保留语义。
- **去重**：转录中反复重复的同一观点合并为一条；笔记中重复记录的内容去重。
- **合并碎片**：杂乱笔记的零散短语、半句话，按主题归类合并成完整表述。
- **纠错**：修正语音转写常见错别字与同音词（人名、专业术语、数字尤其注意）。
- **时间归一**：把"下周三""月底前""下周"等相对时间，基于当前日期换算为具体日期/期限；换算使用日期计算工具，不凭记忆推算（无法换算的保留原表述并注明）。
- **截止状态标注**：待办截止时间与待确认预期解决时间换算为具体日期后，与当前日期比对，交付时标注状态：**已过期 / 临近（7天内）/ 未到期**。
- **口语化转书面**：口语表达转为书面纪要语言，但不改变原意、不新增内容。

## 会议五要素
从清洗后的素材中提取以下要素，找不到的标记为**缺失**（走问答兜底）：

| 要素 | 提取要点 |
| --- | --- |
| 主题 | 会议核心议题；素材无明确主题时从议程/结论归纳 |
| 时间 | 具体到日期（优先内容，缺省默认当天）；素材给时刻也保留 |
| 地点 | 线下会议室 / 线上会议平台 |
| 参会人 | 从转录、笔记、名单中提取姓名；不完整时列已知人员 |
| 主持人 | 主持/引导会议的人；无法判断则标缺失 |

## 内容结构
从素材中提取六类核心内容：
1. **议程**：会议讨论了哪些议题，按实际顺序或主题归并。
2. **发言要点**：各议题下的主要讨论内容、关键信息、各方观点。
3. **决议结论**：会上达成的一致意见、拍板事项、最终结论；每条决议记录 **决策事项 + 决策人 + 决策依据** 三要素：
   - 决策事项：拍板/认可了什么；决策人：谁拍板或谁认可（找不到 → 缺失）；决策依据：依据什么做的决定（如数据、讨论结论、上级要求，找不到 → 缺失）。
   - 三要素缺失走问答兜底；素材无法拆分多条时合并为一条主决议。
4. **待办事项**：每项行动任务，尽量提取**负责人 + 截止时间 + 任务内容**三项；缺谁标谁缺失；截止时间换算后按「截止状态标注」规则标状态。
5. **风险与遗留问题**：未决事项、潜在风险、需后续跟进的问题。
6. **待确认事项**：素材中出现"待确认、待核实、待定、需反馈、等答复、pending"等**尚未落定**的悬置事项，独立成节「待确认事项」，每条记录 **事项内容 + 跟踪人 + 预期解决时间** 三字段。
   - 与**待办事项**区分：待办是已明确要执行的任务；待确认是结论/信息尚未落定、等一个答复或数据的事项。
   - 与**风险与遗留问题**区分：风险是潜在问题、遗留是未决议题；待确认是"等反馈 / 等确认"的悬置项。
   - **条件输出**：素材中不存在待确认事项时不输出该章节；跟踪人、预期解决时间缺失 → 走问答兜底。

提取原则：
- 只在素材中找到依据的内容才写入；找不到依据的不编造。
- 结论、决议与讨论区分清楚：讨论是过程，决议是结果。
- 待办必须落到"谁在什么时间前做什么"，信息不全则缺省留待问答。
- 待确认事项为**条件输出**章节：素材有才单独成节，没有就不输出，不强行凑数。

## 事实来源标注
- 读取素材时先建立来源定位：粘贴文本按段落/要点编号（转录第N段、笔记第N条）；上传文件按"文件名 + 段落/行号"。
- 提取关键事实（数字、金额、日期、人名、决议、待办）时记录其来源位置。
- 交付时在关键项后以括号标注来源，如（转录第3段）、（笔记第2条）、（需求文档·第5段）。
- 仅当来源可精确定位时标注；无法定位的不标注，不编造来源位置。

## 发言人处理
- **默认不保留发言人**：把多人发言合并为整体叙述（如"会上讨论了……""与会人员一致认为……"），不逐句标注"张三：……"。
- **仅在用户特别要求保留发言人时**（如"按发言人整理""谁说的都要标出来"），才以"发言人：内容"的格式保留，并只在转录确有说话人标签时使用；转录无标签则说明无法区分。
- 保留发言人时，附带自动识别出的角色标签（见下节），如"张三（主持人）：……"。

## 发言人角色自动识别
仅在转录**含有说话人标签**（如"张三：……""李四：……"）时启用；转录无标签时不做角色推断，在交付时说明"素材未含说话人标签，无法识别角色"。

### 角色类型与识别特征

| 角色 | 识别特征（满足任一即可推断） | 典型话术信号 |
| --- | --- | --- |
| **主持人** | 开场/收尾、引导议程、点名发言、控制节奏 | "我们开始吧""今天的议程是……""下一个议题""还有谁要补充？""今天就到这里" |
| **决策人** | 拍板、定调、否决或批准方案、最终结论 | "这个就这么定了""我同意方案A""不行，这个方向有问题""最终结论是……" |
| **执行人** | 主动认领任务、汇报进展、承诺交付时间 | "我来跟进""我下周前完成""这块我负责""目前进展是……" |
| **记录人** | 频繁确认要点、复述决议、询问记录是否准确 | "我记一下""刚才的决议是……对吗？""我再确认一下待办" |
| **旁听** | 发言极少（≤2次）、仅附和或提问、不参与决策 | "了解""好的""我有个问题……"（无后续跟进） |

### 识别规则
1. **多信号加权**：不依赖单一话术，综合发言频次、内容特征、议程位置综合判断；同一人可兼具多个角色（如主持人兼决策人），取最主要角色标注，次要角色在备注中说明。
2. **决策人优先**：当某人既像主持人又做了最终决策，标注为"主持人/决策人"。
3. **执行人与待办关联**：被识别为执行人的发言人，其认领的待办事项自动关联到该负责人。
4. **置信度标注**：角色推断置信度分三档——
   - **高**：有明确话术信号 + 行为一致（如开场+收尾+引导议程 = 主持人）
   - **中**：有部分信号但不充分（如只拍板一次但未全程引导 = 可能是决策人）
   - **低**：仅凭发言频次推断（如发言最少 = 可能是旁听）
   中低置信度的角色在交付时标注"（推断）"，高置信度直接标注。
5. **不编造**：无法可靠推断角色时标注"参会人"，不强行分配角色。
6. **角色分布统计**：识别完成后统计各角色人数与发言占比，供可视化卡片使用（见 `visual-card.md`）。

### 输出应用
- **正式纪要**：保留发言人时格式为「姓名（角色）：发言要点」；不保留发言人时角色信息用于辅助判断决议决策人、待办负责人。
- **可视化卡片**：发言人角色分布以图形呈现（见 `visual-card.md`）。
- **行动项清单**：执行人认领的待办自动填入负责人列。
