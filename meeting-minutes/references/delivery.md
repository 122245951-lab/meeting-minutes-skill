## 一键四件套交付
每次生成纪要默认在同一个飞书文档内交付四段（自上而下）：
1. **一页速览卡**：给管理层，一屏看完。
2. **正式纪要**：给存档，完整记录（含决议三件套、待确认事项、执行提示）。
3. **行动项清单**：给执行层，可直接跟进。
4. **可视化卡片**：给所有人，一页静态 HTML 图形化呈现会议全貌（见 `visual-card.md`）。
四段共用同一份提取结果，不重复生成。
若用户只想要其中某一段（如"只要行动项清单""不要可视化卡片"），按用户要求单独输出。

### 可选第五件：Word 制式会议纪要
四件套交付完成后，**必须主动询问用户**是否需要追加一份 Word 版制式会议纪要（表格型，两页 A4 内，内容精简）。
- 用户需要 → 按 `references/word-minutes.md` 生成 `.docx` 并交付。
- 用户不需要 → 不生成，直接结束，不再追问。
- **不默认输出、不静默生成**；本询问与"是否保存模板为个人预设"合并为一次询问。
- Word 版是同一份提取结果的精简投影，不新增信息；生成后四件套内容不变，不回写、不覆盖。

## 一页速览卡
只放最要紧的信息，每条一句话，不展开：
```
一页速览
· 会议：{主题}（{日期}）
· 类型 / 行业：{会议类型} / {行业风格}
· 参会人：{人员}
· 核心结论：1-3 条
· 关键决议：1-3 条（事项｜决策人）
· 主要风险 / 待确认：1-3 条
```

## 正式纪要
按模板骨架生成的完整纪要（见 `template.md` 与 `meeting-types.md`）。

## 行动项清单
待办事项 + 待确认事项合并为可执行清单，表格呈现：
```
| 序号 | 事项 | 负责人/跟踪人 | 截止/预期时间 | 状态 |
| 1 | …… | …… | …… | 未到期 / 临近 / 已过期 |
```
状态列由「截止状态标注」（见 `extraction.md`）计算得出；负责人/跟踪人、时间缺失的标「待补充」，不编造。

## 可视化卡片
- **定位**：一页静态 HTML 卡片，将会议核心信息图形化，让人一眼看懂会议全貌。
- **生成规则**：读取 `references/visual-card.md`，按其规范生成。
- **交付方式**：作为独立 HTML 文件生成，可嵌入飞书文档或单独交付；卡片内容与速览卡/正式纪要/行动项清单一致，不新增信息。
- **包含模块**：会议信息栏、核心结论、决议概览、待办状态分布、风险与待确认、发言人角色分布（有说话人标签时）。
- **多语言**：按输出语言生成卡片；双语需求时标题与标签双语。

## 后果推演提示
- **位置**：正式纪要末尾（待确认事项之后），小节名「执行提示」。
- **依据**：只使用素材中**已出现**的先后依赖或关联关系（如"联调后上线""评审通过后开工"）。
- **格式**：每条 = 前置条件 → 若 {变更/延期} → 受影响事项（全部来自素材）。
- **强制声明**：小节开头标注"以下提示基于本次会议信息推断，仅供参考，不构成对实际结果的承诺。"
- **边界**：素材中不存在明确先后关联时不输出该节；**不新增素材未提及的因果关系**；无法从素材确认的关联不写。

## 来源标注呈现
- 关键事实（数字、金额、日期、人名、决议、待办）在纪要正文中以括号标注来源，如：（转录第3段）、（笔记第2条）、（需求文档·第5段）。
- 标注规则见 `extraction.md`「事实来源标注」；无精确定位时不标注，不编造来源。
- 一页速览卡与行动项清单不逐项标注，保持简洁（正式纪要承载来源）。
