# 会议纪要生成（Meeting Minutes）

## 概述
把用户提供的会议素材（语音转文字全文、杂乱笔记、上传的会议文件）整理成结构化、可直接使用的正式会议纪要。

核心规则：
- **有模板按模板回填**，保留模板固定文案与格式；用户模板可保存为个人预设，下次直接复用
- **无模板自动生成匹配模板**：会议类型从预置清单选择，行业风格从预置清单选择，也可从模板市场选用优质模板
- **字段缺失走问答兜底**，用户说"没有"则留空，不编造
- **日期缺省默认当天**
- **详略按转录长度自适应**（精简 / 标准 / 详细）
- **默认不保留发言人**，除非用户特别要求；转录有说话人标签时自动识别角色（主持人/决策人/执行人/记录人/旁听）
- **多语言混合处理**：中英混合素材自动检测主语言，专业术语保留原文，输出语言由用户指定或跟随主语言
- **待确认事项独立成节**：素材有"待确认/待核实/待定"等未落定事项时，单独输出「待确认事项」章节（事项内容/跟踪人/预期解决时间）
- **差异化增强**：决议三件套、一键四件套交付、相对日期换算与逾期标注、事实来源标注、后果推演提示、可视化卡片（详见参考文件）
- **Word 制式纪要为可选项**：一键四件套交付后**必须询问用户**是否需要 Word 表格型纪要（≤2 页 A4、精简制式）；用户需要才生成，不需要则不生成，绝不默认输出

## 工作流总览
1. 收集并读取全部输入素材，检测素材语言构成
2. 确定会议日期（缺省默认当天）
3. 清洗素材并提取会议要素与内容（六类内容 + 来源定位 + 日期状态 + 发言人角色识别）
3.5 选择会议类型、行业风格、输出语言与模板（用户指定 / 推断确认 / 模板市场 / 个人预设）
4. 模板路由：有模板 → 回填（可保存为个人预设）；无模板 → 按类型套骨架 + 按行业调风格 + 按语言调表达
5. 缺失字段问答兜底
6. 按转录长度确定详略
7. 交付飞书文档（一键四件套）并验证
8. 询问是否需要 Word 制式纪要（可选第五件，需要才生成）

## Step 1 · 收集输入素材与语言检测
先完整读取用户提供的全部输入，不凭印象或二手摘要代替。
- **粘贴文本**（语音转文字全文 / 杂乱笔记 / 混合）：直接使用。
- **上传文件**：按格式读取——`.txt` / `.md` 直接用 Read 工具读取；`.docx` 走 `lark-doc` skill；`.pdf` 走 `doubao-pdf` skill。
- **录音转写**：仅在用户**明确要求**（如"记录这场会""整理这段录音""打开录音"）时才调用 `doubao-record` skill 获取转录；用户没有明确要求时**不得**自行调用。
- 若多种素材并存（如转录 + 笔记 + 模板），全部读取后合并使用，模板单独处理。
- **语言检测**：读取 `references/language.md`，检测素材的语言构成（纯中文 / 纯英文 / 中英混合及比例），记录专业术语与专有名词，为后续输出语言决策提供依据。

## Step 2 · 日期兜底
- 优先从内容提取会议日期（如"本周二""昨天""5月10日"等表述）。
- 内容未提供日期 → **默认当天**（当前系统日期），不进入问答环节。

## Step 3 · 清洗与提取
读取 `references/extraction.md`，按其规则执行：
- **清洗**：去重复、去口头语、合并碎片笔记、纠正转录常见错别字；相对时间基于当前日期换算为具体日期。
- **提取会议五要素**：主题、时间、地点、参会人、主持人；找不到的标记为缺失（进入 Step 5）。
- **提取六类内容**：议程、发言要点、决议结论（含决策事项/决策人/决策依据）、待办事项（含负责人/截止时间/状态）、风险与遗留问题、待确认事项（事项内容/跟踪人/预期解决时间）。
- **发言人角色自动识别**：转录含说话人标签时，读取 `references/extraction.md`「发言人角色识别」规则，自动推断每位发言人的角色（主持人/决策人/执行人/记录人/旁听），并按角色聚合观点；无标签时说明无法区分角色。
- **来源定位**：读取时给素材建立段落/要点编号，关键事实记录来源位置（见 extraction.md「事实来源标注」）。
- **截止状态标注**：待办与待确认的截止/预期时间与当前日期比对，标注 已过期 / 临近（7天内）/ 未到期。
- **发言人**：默认不保留，合并为整体叙述；仅当用户特别要求时才保留发言人维度，保留时附带识别出的角色标签。

## Step 3.5 · 选择会议类型、行业风格、输出语言与模板
读取 `references/meeting-types.md`、`references/industry-styles.md`、`references/language.md` 与 `references/template.md`。
- **会议类型**：用户已指定（如"按周会模板""决策会"）→ 直接使用；未指定 → 从内容推断一个最匹配的类型，并在预置清单中给出候选供用户确认或改选。
- **行业风格**：用户已指定行业（如"金融行业纪要风格"）→ 直接使用；未指定 → 从素材中的行业术语/业务背景推断，并给出预置清单候选供用户确认或改选；无法判断 → 用「通用」风格。
- **输出语言**：用户已指定（如"用英文写""中英双语"）→ 直接使用；未指定 → 按素材主语言输出；中英混合素材中专业术语保留原文不翻译。详见 `language.md`。
- **模板选择**（优先级从高到低）：
  1. 用户本次上传的模板 → 严格回填，并询问是否保存为个人预设
  2. 用户指定的个人预设模板名 → 直接复用已保存模板
  3. 模板市场中的优质模板 → 供用户选用
  4. 无模板 → 按会议类型自动生成骨架
- 类型决定模板骨架，行业风格决定语言基调与字段侧重，输出语言决定表达语言。
- 本选择与 Step 5 缺失字段问答**合并为一次确认**，不重复打扰用户。

## Step 4 · 模板路由
读取 `references/template.md`，按其规则执行：
- **用户提供了模板** → 严格按模板回填：保留模板固定文案、段落顺序、表格结构、字段名；把提取内容填入对应字段；模板字段无对应内容 → 进入 Step 5 问答。行业风格仅调整语言表达，不改模板结构。**回填完成后询问用户是否将此模板保存为个人预设**（命名后存入模板库，下次可直接引用）。
- **用户未提供模板但指定了个人预设或模板市场模板** → 加载对应模板后按回填规则执行。
- **用户未提供模板** → 按 Step 3.5 选定的**会议类型**从 `meeting-types.md` 套用对应骨架，再按**行业风格**从 `industry-styles.md` 调整语言与侧重，按**输出语言**从 `language.md` 调整表达；类型不明用「通用例会」骨架。
- **决议三件套**：骨架中决议章节按"决策事项 / 决策人 / 决策依据"组织。
- **待确认事项**：素材含待确认事项时在骨架末尾追加「待确认事项」章节；没有则不输出。
- **详略自适应**：按转录长度选择精简 / 标准 / 详细版。

## Step 5 · 缺失字段问答兜底
- 汇总所有缺失字段成**一次确认列表**，一次性问用户（不要逐字段轰炸）。
- 提问时给出内容里找到的线索和缺失字段清单，请用户补充或确认。
- 用户回答"没有 / 不知道 / 不用填" → **留空**（不编造内容）。
- 用户回答具体内容 → 填入对应字段。
- 日期缺省默认当天，不进入问答（除非用户主动要求改）。
- 待确认事项的**跟踪人、预期解决时间**，决议的**决策人、决策依据**缺失时，一并纳入此轮问答。
- 会议类型、行业风格、输出语言与模板的选择结果也一并在此轮向用户确认（见 Step 3.5）。

## Step 6 · 交付飞书文档（一键四件套）
读取 `references/delivery.md` 与 `references/visual-card.md`，按"一键四件套"交付：
- 用 `lark-doc` skill 创建飞书文档，同一文档内含四段：**一页速览卡 → 正式纪要 → 行动项清单 → 可视化卡片**。
- **一页速览卡**：给管理层，一屏看完核心信息。
- **正式纪要**：给存档，完整记录（含决议三件套、待确认事项、执行提示、来源标注）。
- **行动项清单**：给执行层，可直接跟进（待办+待确认合并表格，含状态）。
- **可视化卡片**：读取 `references/visual-card.md`，生成一页静态 HTML 可视化卡片，将会议核心信息（信息栏/核心结论/决议/待办状态/风险/待确认/发言人角色分布）以图形化方式呈现，让人一眼看懂；作为飞书文档的附件或独立 HTML 文件交付。
- **有用户模板**：正式纪要段保持模板样式与固定文案，按模板结构排版；速览卡、行动项清单与可视化卡片仍按对应规则输出。
- **无用户模板**：正式纪要段按自动生成的模板骨架排版。
- **待确认事项**：素材含待确认事项时，以「待确认事项」独立章节呈现（每条含事项内容/跟踪人/预期解决时间）。
- **执行提示**：正式纪要末尾按 delivery.md 输出"后果推演提示"，仅基于素材已有关联，并标注推断性质。
- **来源标注**：正式纪要正文中关键事实以括号标注来源。
- **多语言**：按 Step 3.5 确定的输出语言生成；中英双语需求时速览卡与可视化卡片可双语并列。
- 标题规范：`【会议纪要】{会议主题}（{日期}）`。

## Step 7 · 询问并生成 Word 制式会议纪要（可选第五件）
读取 `references/word-minutes.md`，按其规范执行。

- **必须先问，不默认生成**：一键四件套交付完成后**主动询问用户**是否需要 Word 版制式会议纪要（表格型，控制在两页 A4 内，内容精简）。
- **合并询问**：本询问与"是否将模板保存为个人预设"合并为**一次询问**，不额外增加打扰轮次。
- **用户不需要**（答"不用/不需要"）→ 不生成，直接结束，不再追问。
- **用户需要** → 按 `word-minutes.md` 生成 `.docx`：
  - 结构：标题 → 会议基本信息表 → 一、议题与结论 → 二、关键决议 → 三、行动项 → 四、遗留问题 → 签批栏。
  - 排版：A4 纵向、全网格表、表头浅灰底纹、正文 10.5pt、表格行距固定 16pt。
  - 精简：去过程、去佐证（来源标注/决策依据/执行提示一律省略）、去修饰（无 emoji、无彩色字）。
  - 保留：推算类日期的「（推算）」标记与「待补充」字段标记，口径与正式纪要一致。
  - 工具：用 **python-docx** 生成，不依赖 Word COM / pandoc。
  - 校验：生成后回读统计行数，估算页数；**估算超两页时按压缩优先级裁剪后重生成，不交付超页版本**。
- **不新增信息**：Word 版是同一份提取结果的精简投影，不新增事实、不新增推断、不新增素材未提及的因果。
- **命名与交付**：`【会议纪要】{主题}-{日期}.docx`，用 `present_files` 交付，并在回复中说明总行数、估算页数、是否触发压缩。

## 验证
交付前逐项核对：
- 全部输入已完整读取，语言构成已检测
- 每个模板字段都已处理（填了内容 / 走了问答 / 留空）
- 日期已确定（内容提取或默认当天）
- 发言人角色识别结果已验证（有标签时角色推断合理，无标签时已说明）
- 输出语言符合用户要求，专业术语保留原文
- 待确认事项、决议三件套、截止状态、来源标注、执行提示均按规则输出，无编造内容
- 执行提示仅含素材已出现的关联，且带推断声明
- 可视化卡片已生成且信息准确、布局完整
- 回读生成的飞书文档，确认结构与内容正确
- 已按 Step 7 询问用户是否需要 Word 制式纪要；若需要，Word 版已生成、未超两页、保留推算与待补充标记、无新增信息
